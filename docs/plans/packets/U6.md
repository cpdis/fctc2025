# U6 — Screenshot modality (WhatsApp poll OCR import)

Read `_conventions.md` first. Dependencies: U5 (real), U4 (hands results to the
ChecklistView draft). Blocks: U8.

## Objective

Import 1–n screenshots of a WhatsApp poll's **"View votes" screen** (resolved Q4),
OCR on-device, and pre-check matched members on the Review screen — proposals only,
the human confirms.

**Post-U5 notes (orchestrator):** `PollScreenshotParser` already delegates to U5's
`PollLineScanner` and takes `[String]` OCR lines — extend that pipeline, do not
duplicate scanner logic. Matcher semantics are as-built and fixture-encoded: a unique
first name (`Kate`→`Kate B`) auto-matches; shared first names (`Alex`, `Dan`,
`Laura`) are always ambiguous; full-name near-misses (`Dan Brown`→`Dan B`) cap at
the suggestion tier. Treat these as settled.

## Deliverables

1. **`Intelligence/PollScreenshotParser.swift`** (Kit) — takes `CGImage`s, runs
   `VNRecognizeTextRequest` (`.accurate`, `en`, no language correction — names!),
   orders observations top-to-bottom per image, emits plain text lines →
   `NameExtractor` (OCR mode) → union across screenshots with dedupe on normalized
   raw string. Pure orchestration; Vision calls behind `protocol TextRecognizer`
   seam so parsing logic tests run without Vision (fixture `.ocr.txt` lines stand in
   for recognizer output).
2. **`Views/ScreenshotImportView`** — sheet flow from ChecklistView toolbar
   ("Import poll…"): `PhotosPicker` multi-select (screenshots filter), thumbnail
   strip, progress while OCR runs, then a **triage list**: auto-checked matches
   (tier `.match`), tappable suggestions ("Did you mean Cam?"), ambiguous groups
   requiring an explicit pick (`Alex 👑` vs `Alex B` vs `Alex Kr`), unmatched names
   with "Add as new person" / "Map to existing…" / ignore. Apply → merges proposals
   into the `AttendanceDraft` with `.ocr` provenance and returns to ChecklistView.
3. **Nameless-card detection**: when the extractor flags `.namelessPollCard`, show
   the coach hint ("Open the poll and tap View votes, screenshot that screen")
   instead of an empty result.
4. **One-time coach screen** — first launch of the import flow: 2-step illustrated
   instructions (SF Symbols art is fine; no bundled WhatsApp imagery), "don't show
   again" persisted.
5. **Tests** (Kit): parser with fake recognizer over the fixture line-dumps —
   multi-screenshot union/dedupe, ordering stability, triage bucketing per tier,
   nameless-card path. UI test plan for the triage flow (Mac-run).

## Acceptance

- All `fixtures/attendance/poll-*.ocr.txt` expectations reproduced through the full
  parser→matcher→triage pipeline (minus Vision itself).
- Poll "yes" votes arrive as *proposals*, never silently committed (R4) — assert the
  draft requires explicit Apply and the Confirm step still gates the sheet write.
- Memory-sane: images downscaled before OCR if > 4MP; originals never persisted.
