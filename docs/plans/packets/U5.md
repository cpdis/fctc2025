# U5 — NameMatcher + NameExtractor implementations (pure intelligence layer)

Read `_conventions.md` first. Dependencies: U1 only (pure Swift — can run parallel
with U2/U3). Blocks: U6, U7.

## Objective

The shared brain that turns messy candidate strings (from OCR or voice) into
roster-anchored proposals, with the ambiguity discipline the real roster demands.

## Deliverables (in `ios/FCTCAttendanceKit/Intelligence/`)

1. **`NameMatcher.swift`** — pure struct, roster injected:
   - Normalization: casefold, strip diacritics/emoji/punctuation (`Alex 👑` ↔
     `alex`), collapse whitespace.
   - Scoring: exact-normalized = 1.0; else max of Jaro-Winkler and
     normalized-Levenshtein over (full name, first token); nickname table applied
     pre-score, mapping common long-forms/variants → canonical sheet names
     (`Colin→Col`, `Cameron→Cam`, `Daniel→Dan`, `Timothy→Tim`, `Alexander→Alex`,
     ASR homophones like `Colm→Col`, `Camm→Cam`; table is a plain dictionary,
     easy to extend).
   - **Ambiguity rule (non-negotiable):** if ≥2 roster names score within 0.1 of the
     top score, or the query maps to a first-name shared by multiple members
     (`Alex 👑`/`Alex B`/`Alex Kr`, `Dan`/`Dan B`, `Laura E`/`Laura K`), the result
     is `.ambiguous([candidates])` — NEVER auto-pick.
   - Tiers: `.match(name)` ≥ 0.85 (unique), `.suggestion(name, score)` 0.6–0.85,
     `.ambiguous([...])`, `.unmatched(raw)` < 0.6.
2. **`NameExtractor.swift`** — `protocol NameExtractor { func extract(from text:
   String, context: ExtractionContext) async -> ExtractedAttendance }` where
   `ExtractedAttendance = { rawNames: [String], plusOnes: Int?, distanceKm: Double? }`
   (extraction is roster-blind; matching is NameMatcher's job downstream).
3. **`HeuristicExtractor.swift`** — deterministic, fully tested:
   - Voice mode: strip stop-phrases ("came", "was there", "said they", "turned up",
     "and", "plus"); parse `distanceKm` from "8.7k / eight point seven k / 12 kays";
     parse `plusOnes` from "plus two / two guests / a plus one"; remaining
     capitalized-ish tokens → rawNames.
   - OCR mode: drop WhatsApp chrome lines (option labels "Yes/No/…", "N votes",
     percentages, timestamps, "View votes", weekday-question lines); remaining
     short lines → rawNames; detect the nameless-poll-card case (options+counts but
     zero name lines) and flag it (`context.warning = .namelessPollCard`).
4. **`ModelExtractor.swift`** — FoundationModels guided generation: availability
   check (`SystemLanguageModel.default.availability`), `@Generable` struct matching
   `ExtractedAttendance`, tight instructions prompt ("extract only names present in
   the text; do not guess"), graceful fallback to `HeuristicExtractor` on
   unavailable/error/low-confidence. Behind
   `protocol ModelGateway` seam so tests can fake availability + outputs without the
   framework.
5. **Tests** — table-driven over `fixtures/attendance/*.transcript.txt` and
   `*.ocr.txt` + expected JSONs (load fixtures from the test bundle): every roster
   collision case; OCR typos ("Scot t", "Gra nt"); nickname hits; ambiguity
   never-auto-pick assertions; distance/guest phrase matrix; nameless-card warning;
   extractor selection logic via fake `ModelGateway`.

## Acceptance

- 100% of fixture expectations pass under `HeuristicExtractor` + `NameMatcher`.
- `ModelExtractor` compiles-plausible with real FoundationModels API names (verify
  against Apple docs; note any uncertainty in HANDOFF for Mac verification).
- No Foundation-external imports in `NameMatcher`/`HeuristicExtractor` (pure, portable).
