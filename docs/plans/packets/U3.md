# U3 — SheetAPI client, SwiftData models, SyncEngine (outbox)

Read `_conventions.md` first. Dependencies: U1 scaffold + the frozen contract
(U2 need not be deployed — build against the contract, test against a stub).
Blocks: U4.

## Objective

The app-side data layer: typed client for the four actions, persistent models, and an
offline-tolerant outbox so a confirmed submission always eventually lands.

## Deliverables (all in `ios/FCTCAttendanceKit/`)

1. **`Services/SheetAPI.swift`** — `actor SheetAPI`: async methods `getState()`,
   `submitAttendance(_:)`, `addMember(name:)`, `addRun(_:)`; `Codable` DTOs mirroring
   the contract exactly (incl. `conflict` payload); transport behind
   `protocol HTTPTransport { func post(_ body: Data) async throws -> Data }` with a
   `URLSessionTransport` default (endpoint URL + secret injected from
   `AppConfig`); decode `{ok:false}` into typed `SheetAPIError` cases.
2. **`Models/`** — SwiftData `@Model`s:
   - `Member` (name = canonical sheet name, colIndex, isNew flag pre-sync).
   - `ScheduledRun` (rowIndex, date, meet, run, approxKm, actualKm?, attendees,
     plusOnes) — cache of `getState().runs`.
   - `PendingSubmission` (draft snapshot: rowIndex, expectedDate, expectedRun,
     attendees, plusOnes, **guestNames [local-only, per resolved Q2]**, actualKm,
     mode, createdAt, attemptCount, lastError?, state: queued/inFlight/conflict/done).
   - `AttendanceDraft` (in-memory, not persisted): checked set with per-name
     provenance (`manual`/`ocr`/`voice`), guestNames, plusOnes derived =
     guestNames.count unless manually overridden, actualKm.
3. **`Services/SyncEngine.swift`** — `actor` owning the outbox: enqueue on confirm;
   drain loop with exponential backoff (2/4/8/16s then park until next foreground or
   `refresh()`); network-unreachable ≠ failure (stay queued); contract `conflict`
   response → mark submission `.conflict` with server state attached and emit an
   `AsyncStream<SyncEvent>` the UI can observe; success updates the `ScheduledRun`
   cache from the response; `refreshState()` re-pulls `getState` and reconciles
   roster/run cache (server wins; local `isNew` members reconcile by name).
4. **Tests (`FCTCAttendanceKitTests`)** with a scripted `StubTransport` (canned
   response sequences): happy path; offline → queued → drains on recovery; idempotent
   re-submit after ambiguous timeout (send twice, second is a no-op server-side —
   assert client tolerates duplicate success); conflict surfacing carries fresh
   state; addMember optimistic insert then reconcile; decode of every error code.

## Acceptance

- Tests compile-plausible and logically complete (compile/run verification on Mac —
  note in HANDOFF); zero UI code; zero third-party deps.
- No `URLSession` outside `URLSessionTransport`; all times/backoff injectable
  (`Clock`-style seam) so tests don't sleep.
- DTO field names match the contract JSON keys byte-for-byte.
