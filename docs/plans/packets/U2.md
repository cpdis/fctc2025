# U2 — Apps Script Web App API (the canonical write layer)

Read `_conventions.md` first. Dependencies: U1. Blocks: U3 (contract), U8 (deploy).
This unit owns the frozen API contract in `_conventions.md` — implement it exactly;
propose changes via plan PR, never unilaterally.

## Objective

Implement the four-action Web App that is the ONLY writer from the app to the Google
Sheet, with sheet-geometry logic pure and Node-tested against real season fixtures.

## Deliverables

1. **`apps-script/SheetOps.js`** — pure, side-effect-free functions over a 2-D cell
   array (works in Node and Apps Script; no `SpreadsheetApp` calls here):
   - `findHeaderRow(grid)` — port the rule from `src/utils/dataParser.js`: the row
     whose first cell is `Date` and which contains `Run` and `Actual kms`. Tolerant of
     drifting position/summary bands above.
   - `memberBand(grid, headerRow)` → `[{name, colIndex}]` — every column strictly
     between `Actual kms` and `+1's`.
   - `findRunRow(grid, headerRow, {date, run})` and `listRuns(...)` — a run is
     identified by Date + Run (two runs can share a date, e.g. 26-Jan).
   - `revisionHash(grid, headerRow)` — stable hash (e.g. FNV-1a over normalized
     header + run-band cells). Deterministic across Node/Apps Script string handling.
   - `alphabeticalInsertIndex(band, newName)` — case/diacritic/emoji-insensitive
     (`Alex 👑` sorts as `Alex`); duplicate detection under the same normalization.
   - `buildRowWrite(band, attendees, plusOnes, actualKm)` → the exact value array
     (`x`/`""` per member cell) for a `submitAttendance`, mode-aware:
     `merge` = union with existing marks; `overwrite` = absolute (may clear marks —
     resolved Q1).
   - `dateOrderedInsertIndex(runs, newDate)` for `addRun`.
2. **`apps-script/Code.gs`** — the impure shell: `doPost` router; secret check against
   `PropertiesService` script property `SHARED_SECRET` (constant-time-ish compare);
   `LockService.getScriptLock()` around every read-check-write; reads the tab named
   by script property `SEASON_SHEET_NAME` (e.g. `2026`); maps SheetOps outputs to
   `Range` writes; structured errors (`bad_secret`, `unknown_action`, `row_mismatch`,
   `stale_revision`, `duplicate_member`, `bad_payload`); `submitAttendance` returns
   `conflict` with fresh `getState` payload instead of writing when row identity or
   `baseRevision` don't match. Never writes outside the granted cells (conventions
   invariant) — assert indices against the band before writing.
3. **`apps-script/test/sheetops.checks.js`** (extend U1's file; register any new
   files in `test/index.js` — see conventions ruling) — `node --test`, table-driven against
   `fixtures/attendance/2025.csv` and `2026.csv` (parse CSV with a tiny local parser
   handling quoted commas, e.g. `"Fri, 2-Jan"`): header detection on both seasons'
   drifted layouts; band extraction (2025: 30 members, 2026: 33 — assert exact
   names); two-runs-one-date disambiguation; alphabetical insert positions incl.
   `Alex B` between `Alex 👑` and `Alex Kr`, prefix cases (`Dan B` after `Dan`),
   duplicate rejection (`col` vs `Col`); merge vs overwrite write-arrays; revision
   stability + sensitivity.
4. **`apps-script/test/smoke.md`** — scripted manual smoke plan Colin runs once
   against a COPY of the real sheet: deploy, `getState` roundtrip, submit, re-get,
   conflict path (edit sheet between get/submit), `addMember`, formula-intactness
   check (`Total Attendance per run` still computes on the touched row).

## Acceptance

- `node --test apps-script/test` green; dashboard `npm test` untouched/green.
- `Code.gs` uses SheetOps for ALL geometry decisions (no duplicated header/band
  logic in the impure shell).
- Every response shape matches the frozen contract verbatim (write a contract-shape
  test that validates example responses against the documented keys).
