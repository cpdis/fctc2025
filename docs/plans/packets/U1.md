# U1 — Repo scaffolding & fixtures

Read `_conventions.md` first. Dependencies: none. Blocks: everything else.

## Objective

Give the repo its iOS + Apps Script skeleton and the shared fixtures, without
disturbing the existing web dashboard.

## Deliverables

1. **`ios/` — Xcode-26 project via XcodeGen** (no hand-written `.pbxproj`; Colin runs
   `xcodegen generate` on his Mac):
   - `ios/project.yml`: app target `FCTCAttendance` (iOS deployment target 26.0,
     SwiftUI lifecycle, bundle id `com.cpdis.fctc-attendance`), local framework/library
     target `FCTCAttendanceKit` (all non-UI logic lives here so it's unit-testable),
     test target `FCTCAttendanceKitTests`. Info.plist entries for Photo Library,
     Speech Recognition, and Microphone usage descriptions.
   - `ios/FCTCAttendance/` app entry: `FCTCAttendanceApp.swift` (SwiftData
     `ModelContainer` bootstrap), placeholder `HomeView` (Reminders-style large-title
     list with static rows — real UI comes in U4).
   - `ios/FCTCAttendanceKit/` with empty-but-compiling stubs establishing the module
     map from the plan: `Models/` (`Member.swift`, `Run.swift`,
     `AttendanceDraft.swift`, `PendingSubmission.swift` — SwiftData `@Model` where
     persistent; include `Guest` names on drafts/submissions per resolved Q2),
     `Services/` (`SheetAPI.swift`, `SyncEngine.swift` protocol stubs),
     `Intelligence/` (`NameMatcher.swift`, `NameExtractor.swift` protocol,
     `PollScreenshotParser.swift`, `VoiceEntryParser.swift` stubs).
   - One trivial compiling test per stub area in `FCTCAttendanceKitTests`.
2. **`apps-script/` scaffold**: `appsscript.json` (V8, webapp access ANYONE_ANONYMOUS,
   execute as USER_DEPLOYING), `.clasp.json.example` (script ID placeholder + note),
   `Code.gs` stub (`doPost` returning `{ok:false,error:"not_implemented"}`),
   `SheetOps.js` empty module with the dual-environment pattern (plain functions +
   `if (typeof module !== 'undefined') module.exports = {...}` so Node can test what
   Apps Script runs), `test/` with one passing `node --test` smoke test,
   `README.md` (clasp push/deploy runbook, secret setup via Script Properties).
3. **`fixtures/attendance/`**:
   - `2025.csv`, `2026.csv` — copies of `src/test/fixtures/` seasons (do not edit
     originals).
   - `poll-1.ocr.txt`, `poll-2.ocr.txt`, `poll-card-nameless.ocr.txt` — realistic
     WhatsApp "View votes" OCR line dumps (option headers like "Yes ✓ 14 votes",
     names from the 2026 roster incl. the `Alex`/`Dan`/`Laura` collisions and a few
     OCR typos like "Scot t"), plus the nameless poll-card negative case; each with
     `*.expected.json` (`{names: [...], unmatchedRaw: [...]}` etc.).
   - `voice-1..3.transcript.txt` + expected JSON (`{names, plusOnes, distanceKm}`),
     covering "plus two guests", "eight point seven k", conjunction-heavy phrasing.
4. **Repo plumbing**: `.gitignore` additions (Xcode: `xcuserdata/`, `*.xcodeproj` —
   generated, `DerivedData/`; clasp: `.clasp.json`); new CI workflow
   `.github/workflows/attendance-tests.yml` running `node --test apps-script/test`
   on PRs touching `apps-script/` or `fixtures/attendance/`; README.md gains a short
   "Attendance app" section linking the plan (this is the one README edit allowed).

## Acceptance

- `node --test apps-script/test` passes; `npm test` (dashboard) still green.
- `ios/project.yml` is valid YAML; Swift files are syntactically plausible Swift 6
  (state in HANDOFF that compile verification needs Colin's Mac).
- Fixtures' expected JSONs parse (`node -e` check) and roster names match the real
  2026 header names exactly (see `public/data/2026.csv` row starting `Date,Meet,Run`).
- No diffs outside `ios/`, `apps-script/`, `fixtures/`, `.gitignore`,
  `.github/workflows/attendance-tests.yml`, `README.md`.
