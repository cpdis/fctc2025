# U4 — Checklist modality, Review & Confirm, run picker (the core UI)

Read `_conventions.md` first. Dependencies: U3 (real), U5 (interfaces only — accept
proposals from any `NameExtractor` via the draft model). Blocks: U6/U7 handoff, U8.

## Objective

The Reminders-styled UI that every modality lands in. Plan section "Design language:
Apple Reminders as the reference" is the spec — reread it before building.

## Deliverables (in `ios/FCTCAttendance/Views/` + view models in Kit)

1. **`HomeView`** — large-title "FCTC" screen, Reminders-style: summary tiles row
   (This Week count, Unsynced count with badge), then tinted circular-icon rows:
   Today's Run, All Runs, Past Runs, Outbox, Settings.
2. **`RunPickerView`** — sectioned list (Today / This Week / Later / Past); default
   selection rule (R7): most recent scheduled run with date ≤ now, skipping
   already-recorded rows unless none pending; rows show `Meet · Run · Approx kms`
   and a recorded-checkmark; create-run fallback (sheet-presented form → `addRun`).
3. **`ChecklistView`** (Review & Confirm — THE screen):
   - Detail rows above the list, Reminders-style: `Actual kms` (decimal pad,
     pre-filled with Approx kms), Guests (navigates to guest-name editor; the row
     shows derived count that maps to `+1's` — resolved Q2).
   - Member list: grouped inset, one row per roster member, **circular check toggle
     on the left** that fills with accent color; trailing provenance badge when a
     check came from OCR/voice proposal (`sparkles` for model-proposed, distinct
     for suggested-not-auto); tap toggles; swipe-to-uncheck; pull-down search.
   - Quick-add pinned row "Add person…" — inline text field like Reminders' New
     Reminder; commit → optimistic roster insert + `addMember` via SyncEngine; can
     also promote a previously-stored guest name (offer matching guests as you type).
   - Confirm toolbar button: disabled until draft differs from sheet state; if the
     target row already has attendance recorded, present the **merge/overwrite
     dialog** (merge = union; overwrite = absolute, may uncheck — resolved Q1) with
     a small diff summary ("will add 3, remove 1"). Confirm → enqueue on SyncEngine,
     haptic, return Home showing outbox badge.
4. **`OutboxView`** — pending/conflict submissions; conflict rows open a resolution
   sheet (shows server-vs-local diff, pick merge/overwrite/discard → re-enqueue).
5. **`SettingsView`** — endpoint URL + shared secret (Keychain-stored), device name,
   "re-fetch roster" action. (QR-import of config arrives in U8 — leave a seam.)
6. **State plumbing** — observable view models in Kit consuming SyncEngine's
   `AsyncStream`; all views work from SwiftData cache when offline.

## Acceptance

- XCUITest plans (runnable on Mac; write them, verify by inspection here): happy
  path record→confirm→outbox-drain; already-recorded warning path; offline queue
  visible then drains; add-person appears alphabetically instantly.
- Every interactive element reachable with Dynamic Type XL and VoiceOver labels set
  (member rows announce name + checked state).
- Stock components only; no custom drawing beyond the circular toggle if the stock
  toggle can't match Reminders' look.
